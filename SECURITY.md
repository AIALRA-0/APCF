# Security policy

Do not report credentials, private transcripts, tokens, source-history secrets or sensitive workspace paths in a public GitHub issue. Use GitHub's private vulnerability reporting if enabled, or contact the repository owner through an established private channel.

The public release is assembled from a clean, verified Core candidate, not from the private development repository's original Git history. A PUBLIC metadata label is not a secret scanner or a legal authorization.

Installation should verify release SHA-256, reject unsafe archive paths and existing Agent instruction conflicts, and preserve the original application's Git history, source files and build pipeline. Public deployment and arbitrary code execution always require separate authorized review.
